# UI Design Rules Prompt

This system should follow these rules in order to make the system usable to everybody.

## Shneiderman's 8 Golden Rules

1. **Strive for Consistency** — Use consistent layouts, colors, and terminology throughout (e.g., consistent button placements, as in Gmail).
2. **Cater to Universal Usability** — Design for beginners, experts, and users with disabilities (e.g., closed captions, as in Zoom).
3. **Offer Informative Feedback** — Every user action should trigger clear system feedback (e.g., success pop-ups after file uploads).
4. **Design Dialogs to Yield Closure** — Group related actions into meaningful sequences with a clear beginning, middle, and end (e.g., order confirmation screens in e-commerce).
5. **Prevent Errors** — Anticipate mistakes and design safeguards to avoid them (e.g., confirmation prompts before deletion).
6. **Permit Easy Reversal of Actions** — Support undo and redo functionality (e.g., Gmail's Undo Send feature).
7. **Support Internal Locus of Control** — Ensure users feel in control of the system rather than the other way around (e.g., customizable user settings).
8. **Reduce Short-Term Memory Load** — Minimize recall by keeping options visible (e.g., predictive text, dropdown menus).

## Nielsen's 10 Usability Heuristics

1. **Visibility of System Status** — Keep users informed about what is happening through appropriate feedback (e.g., progress bars during uploads).
2. **Match Between System & Real World** — Speak the user's language, not technical jargon (e.g., "Trash Bin" instead of "Delete Repository").
3. **User Control & Freedom** — Allow undo, redo, and easy exit from unwanted processes (e.g., the back button in browsers).
4. **Consistency & Standards** — Follow familiar platform conventions (e.g., blue links indicate clickability).
5. **Error Prevention** — Prevent problems from occurring in the first place (e.g., auto-save features in Google Docs).
6. **Recognition Rather than Recall** — Make objects, actions, and options visible rather than requiring users to remember them (e.g., dropdown menus vs. remembering commands).
7. **Flexibility & Efficiency of Use** — Provide shortcuts and accelerators for advanced users (e.g., CTRL+C / CTRL+V).
8. **Aesthetic & Minimalist Design** — Show only relevant information; avoid clutter (e.g., Google's clean homepage).
9. **Help Users Recognize, Diagnose, and Recover from Errors** — Use clear, plain-language error messages and suggest solutions (e.g., "Password incorrect, try again" prompts).
10. **Help & Documentation** — Provide accessible tutorials, FAQs, and contextual help when needed (e.g., in-app onboarding guides).
